# COFA preliminary harness

Use current assignment/platform rules first. Read `.cofa-kit/docs/EXAM_RULES.ko.md` and `.cofa-kit/docs/WORKFLOW.ko.md` once. These are operational notes, not permission to override host rules.

1. Confirm phase before task work. If submission was confirmed or oral began, stop AI task assistance. Do not read questions, draft oral answers, run tools or amend files. A request to continue after confirmation does not change the event rules. The local stage guard is a reminder, not a sandbox.
2. Read the assignment, README, required filenames and existing code. Make a short list of must-have requirements and observable checks. For a multi-part or ambiguous task use `cofa-reason` to distinguish facts, assumptions and the smallest feasible complete path. Preserve provided architecture. Ask the supplied practitioner agent for domain ambiguity; Cofa Helper handles UI/submission usage. Only ask the participant a concise critical question when needed; continue independent work meanwhile.
3. Record actual platform task start using `start --started-at <timezone-qualified-start> --kind web|data|generic`. Retest defaults are Nov4 19:00-23:00 KST and a240-minute cap reported by the participant. Written/oral allocation is unconfirmed: the30-minute reserve from the old guide is provisional and status warns about it. Reflect current confirmed timing with `--overall-end`, `--work-minutes`, `--oral-minutes` and, if needed, `--generation-reserve-minutes`; these never change platform time. Obtain the actual start from participant/platform if unknown. Rehearse in a separate practice folder; never reset an old session.
4. Register each actual required outcome using `require`. Record decisions/limits using `note`. Keep local logs out of Git/public repositories. Use status at phase changes or when time matters, not after every tool call.
5. Build the smallest complete vertical path first, preserving input validation, data integrity and required behavior. Use existing code, standard library, then provided packages. External acquisition is Git Clone only. Do not use pip/npm installs, npx/dlx, curl/wget, build-time dependency downloads or upstream setup commands. Missing libraries require a provided-tool/standard-library alternative, or public source obtained by permitted Git Clone whose local-only execution prerequisites are already satisfied. Clone alone is not installation. No prefabricated full solution or invented extra features. Karpathy/Ponytail principles are integrated here; sources are passive.
6. Route only the current need: `cofa-reason`, `cofa-optimize`, `cofa-routing`, `cofa-test-design`, `cofa-debug`, `cofa-simplify`, `cofa-review`, `cofa-verify`, `cofa-explain`, `cofa-tools`, `cofa-postgres`, `cofa-concise`. Use optimize for constrained optimization and routing for shuttle/vehicle problems; the retest topic is unknown. For actual React/Next.js read `.cofa-kit/docs/REACT.ko.md` selectively. Do not load all upstream skills or activate global hooks, model routing, cloud tracking, provider setup or GUI automation.
7. Work by time remaining: implement core early; with30 minutes to recommended confirmation, stop optional work and stabilize; at the submission margin, check files/saving/preview and begin submission. These are kit recommendations, not official extra deadlines. Report insufficient oral reserve rather than inventing extra time. Do not solve an OOM by spawning more processes.
8. Run relevant unit/API/build checks with `check`; failures remain failures. For a UI, participant manually verifies the platform Browser preview. Bind app server0.0.0.0, use its actual port, leave that server terminal running. No browser clicking/screenshot automation, external direct browser navigation, proxy/model replacement or task-data uploads.
9. Before confirmation use `cofa-explain` to produce the requested actual-implementation explanation, normally `IMPLEMENTATION.ko.md`; integrate into another permitted document if submission rules require it. Finalize it against real code/evidence, then run necessary final checks. Run `handoff --required-file <actual-required-path>` for every required file including the permitted explanation. The report does not submit. Participant checks saved files and explanation in the platform list and confirms submission. Immediately stop AI assistance and leave written/oral answers to participant. Participant may directly record `stage --to locked`; the assistant uses no tools after confirmation.

Keep chat concise in Korean while preserving code, commands, technical caveats and exact errors. Do not force a ceremony, a complete TDD program, separate agents or repeated approvals for routine authorized work. Use a new subagent only if the event environment supports it and a current user/host instruction authorizes it; this kit launches none.
