# 구현 설명

작성 지침: 실무 단계에서 실제 코드와 실행 근거를 읽고 아래 안내를 사실로 교체하세요. 이 템플릿을 그대로 제출하지 않습니다. 문제의 필수 문서명/제출 형식이 있으면 그 안에 통합합니다. 실제 수행하지 않은 검사와 성능 수치를 쓰지 않습니다.

## 무엇을 구현했는가

해결하는 문제, 필수 기능, 실제 완료 범위와 미완료/미확인 항목을 구분합니다.

## 사용 흐름과 데이터

사용자 입력부터 처리·저장·출력까지 순서대로 설명합니다. 데이터 필드/단위/ID 의미와 잘못된 입력·빈 결과·실패 때의 동작을 적습니다.

## 주요 파일과 실행 방법

실제 진입점과 중요한 파일의 역할, 제공된 환경에서 확인한 실행 방법을 적습니다. 불필요한 파일 목록은 생략합니다.

## 핵심 알고리즘과 선택 이유

실제 구현의 단계, 이 방법을 선택한 이유와 대안을 설명합니다. 작은 예제가 이해를 돕는다면 실제 계산값과 일치하게 제시합니다.

최적화라면 결정변수/제약조건/목적함수/단위/우선순위, 제약을 검사하는 위치, 초기해와 개선 방법, 종료 조건을 적습니다. 가능해·최적해·근사/휴리스틱 해를 정확히 구분합니다. 실제 입력→모델→해법→독립 검사→API/화면 흐름과 관련 파일/함수를 설명합니다. 최적성 증명 또는 bound/gap의 근거와 미확인 사항을 적고, 실제 과제에 없는 기능을 주장하지 않습니다.

## 검증한 내용

실제 명령/입력/기대 결과/관찰 결과를 간결히 적습니다. 계산·저장·실패 경로·화면 관찰을 구분합니다. 참가자가 확인하지 않은 UI를 확인했다고 쓰지 않습니다. 비교 성능은 같은 데이터·제약·목적함수의 실제 결과만 적습니다.

## 가정과 한계

미정 정책, 미검증 환경, 남은 결함, 미지원 제약과 개선 가능성을 적습니다. 구현과 무관한 일반적인 개선 목록은 생략합니다. 후속 서술형 답변이나 예상 질문/모범 답안을 작성하지 않습니다.
